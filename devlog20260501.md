### Részletek

**#1 Tracked changes** — OOXML `<w:ins>`/`<w:del>` markup teljes támogatás:
- `docx_track_replace_paragraph` — text → `<w:del>`(eredeti) + `<w:ins>`(új)
- `docx_track_insert_after`, `docx_track_delete_paragraph`
- `docx_accept_all_revisions`, `docx_reject_all_revisions`, `docx_list_revisions`

**#2 Comment threading** — `commentsExtended.xml` parent/child linkek:
- `docx_add_comment` — első komment + Content_Types + relationships auto-regisztráció
- `docx_list_comments`
- `docx_reply_to_comment` — új komment + `w15:paraIdParent` link a parenthez
- `docx_resolve_comment` — `w15:done="1"` toggle

**#5 Self-healing parser** — quality scoring heurisztikák:
- `parse_with_quality(file_id, force_vision=False, quality_threshold=0.55)`
- Score: char density / page, replacement char ratio, printable ratio, alpha ratio
- Ha a natív parser score < threshold → Kimi K2.6 vision fallback per page (rasterize → OCR)
- Visszaadja amelyik módszer magasabb score-t kapott, full provenance metadata-val

**#6 Chart redraw** — render → vision → rebuild:
- Kimi K2.6 vision szigorú JSON-ban kinyeri: chart_type, title, axes, categories, series, values
- matplotlib-szal újrarajzolja új palettával / brand-del / chart_type override-dal
- Output új PNG file_id, kész `insert_image`-re

**#8 Term consistency** — case-sensitive surface-form variation flagging:
- Glossary mode: `[{canonical, allowed_variants, kind}]` explicit lista
- Auto-detect mode: Kimi K2.6 azonosít candidate term-eket az első dokumentumból
- Output flagged_variants (nem-allowed surface forms) + per-document counts

**#9 MTMT integráció** — kettéosztva:
- `extract_citations` — működik most; Kimi K2.6 dedup + struktúra (authors/title/year/journal/doi/isbn)
- `mtmt_search_author`, `mtmt_verify_citation` — placeholder, MTMT REST API publikus dokumentációja gyenge

**#10 do_task mega-tool** — recursive sub-agent:
- `do_task(goal, file_ids, max_iters=8)` spawn új run_agent loopot
- `AgentState.do_task_depth` field — depth ≥ 1 esetén refuse (max 1 szint mély)
- Sub-agent kapja a primary file-t + extra fájlok említését az instrukcióban

### Felfedezett bugok itt — mind permanently javítva production kódban:

1. **SiliconFlow Kimi K2.6 vision + `response_format: json_object` → HTTP 500**
   - Diagnosztika: ugyanaz a prompt JSON output flag nélkül siker, flag-gel 500
   - **Fix:** `vision._call` sosem küldi a `response_format`-ot, prompt-instruction-szel kérünk JSON-t, `strict=False` parser fallback hibás kontroll karakterekre

2. **Vision OCR ReadTimeout 120s alatt heavy fotókon**
   - **Fix:** vision-specifikus 240s timeout (`max(LLM_TIMEOUT_S, 240)`), `httpx.ReadTimeout` is a retry list-en

3. **Nagy képek (>1.8MB / >2856px) → 400 Bad Request a vision endpoint-on**
   - **Fix:** `vision.image_to_data_url` auto-downscale Pillow-val: long edge cap 1280px, file size cap 2MB, JPEG quality 85, optimize=True

4. **scipy hiányzik a venv-ből** — csak teszt scriptben volt szükséges, k-nearest-neighbour edge selection-re cseréltem

## 5. Agent self-correction loop élesben

A user kritikus correction-je: **"NE TE oldd meg! Az agentnek kell megoldania!!!"** — a feature-ek központi pontja az agent-driven workflow, nem manuális python fix scriptek. (Mentve `feedback_agent_driven_fixes.md`-ben.)

Cover overlap fix kérése `run_agent`-en keresztül. Az első futás trace:
- iter 1: render
- iter 2: describe_image — "overlap detected"
- iter 3: tool call **raw text-ként a content-ben** (`<|tool_call_begin|>functions.count_matches:3...`)
- iter 4: agent stops — Kimi nem strukturált tool_calls-t adott

### 4 strukturális fix amit ez a real-world test feltárt:

1. **Kimi-native tool call parser fallback**
   - Kimi K2.6 néha a tool call-okat raw text-ként adja vissza a content-ben az OpenAI-compat tool_calls array helyett
   - **Fix:** `_parse_kimi_text_tool_calls()` regex parser, ha a strukturált mező üres, parsolja a `<|tool_call_begin|>functions.NAME:N<|tool_call_argument_begin|>{json}<|tool_call_end|>` formátumot
   - Plus a content-ből cleaning a marker text-eket hogy következő turn ne keveredjen

2. **`reasoning_content` field passthrough**
   - Kimi K2.6 thinking mode visszaad egy `reasoning_content` field-et — ezt kötelező visszapasszolni az API-nak
   - Hiba mintha kihagynánk: `400 code 20015: "reasoning_content in the thinking mode must be passed back"`
   - **Fix:** asst_msg-ben `reasoning_content` field copy

3. **Új tool: `pptx_modify_textbox`**
   - A meglévő `pptx_set_slide_styles` csak built-in placeholder-eket tudott módosítani; a custom-elhelyezett textbox-ok érinthetetlenek
   - **Fix:** új tool ami text-substring alapján megtalálja a shape-t és módosítja: font_size_pt, bold, italic, font_color, left/top/width/height_inches, new_text replacement
   - Most az agent surgically tudja fixálni a vizuális hibákat anélkül hogy az egész slide-ot újraépítse

4. **Visual self-review loop hard rule a SYSTEM_PROMPT-ban**
   - Default workflow most: minden vizuális build/edit után KÖTELEZŐ render → describe_image self-review → fix → re-render (max 2 fix iteráció)
   - Plus külön szabály: SOSE embed-elj tool call-t plain text-ként a content-be, használd a strukturált function-calling channel-t

### Második futás (4 fix után):

```
iter 1: read_document + pptx_render_slide
iter 2: describe_image → "overlap between title and subtitle"
iter 3: pptx_modify_textbox(find_text="Előre, ne hátra!", font_size_pt=44, height_inches=2.5)
iter 4: pptx_render_slide → új preview ✓ overlap megoldva
iter 5: describe_image (self-review check) — vision API transient 500
```

Az iter 4 kép visszaolvasva: **overlap teljesen eltünt**, "Előre, ne hátra!" most egy sorban a 44pt fontnál, subtitle alatta tisztán. Kimi maga csinálta végig — tool kiválasztás, paraméter értékek, geometria becslés.
